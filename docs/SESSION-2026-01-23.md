## Key Architecture Decisions

### Token Efficiency
- **Convener**: 5-minute mail polling (vs continuous)
- **Nudger**: 10-minute patrol cycle (vs 30-second Gas Town pattern)
- **Mail checks**: Simple file reads (very low cost)
- **Model selection**: Sonnet for coordination (3-5x savings vs Opus)

### Philosophy: Support vs Surveillance
Rejected Gas Town's "Witness" terminology in favor of "Nudger":
- 60-minute threshold vs 30-minute (respects deep thinking)
- Gentle nudges vs enforcement
- Escalation after 3 attempts vs automatic intervention
- Support role, not policing

### Session Lifecycle
Agents complete work and exit cleanly (don't wait idle):
- Scholars/Critics: Work → commit → close bead → mail convener → exit
- Convener: Respawns agents fresh for new phases (preserves workspace/identity)
- No "patrol nuking" - agents self-manage completion

## Lessons Learned

1. **Heredoc issues**: Nested heredocs in spawn scripts are fragile; consider separate assignment files
2. **Dynamic patterns > hardcoded lists**: Monitoring should use exclusion patterns, not enumerate names
3. **Token efficiency matters**: 5-10 min polling is sufficient for academic timescales
4. **Model selection**: Sonnet is fine for coordination; save Opus for content
5. **Naming matters**: "Nudger" feels supportive; "Witness" feels surveillant
6. **Agent autonomy**: Self-exit on completion is more respectful than idle waiting

## Philosophy

This session focused on building **infrastructure that respects autonomy**:
- Agents signal completion voluntarily (not detected via surveillance)
- Nudges are supportive, not coercive
- Generous time allowances for deep work
- Token-efficient patterns that work at academic timescales
- Clear role boundaries (coordination vs content creation)

The goal: Create conditions for autonomous intellectual flourishing, not maximize throughput.
